# Fictional coaching example — private-report style

This is a public demonstration using only the companion fictional messages, not
an assessed person or a held-out result. Sources: [selected messages](synthetic-session.md).

**Scope:** one selected design/check episode; no code, command receipt or later
result. Other project decisions and most behavioral lenses are unobserved.

**E1/C1 — contribution.** M1 introduces the cache idea (assistant). In M2 the
person narrows its scope, names freshness as a constraint and proposes two checks.
This supports human product/system constraint awareness and adaptation of an idea;
it does not establish that the person invented the cache or implemented it.

**E1/C2 — verification.** M3 is an assistant success claim. In M4 the person
requests relevant receipts and connects them to the identified freshness and
export behavior. This is a supported critical/verification choice. We cannot
conclude the checks ran, the cache is correct or the person has general test-engineering
expertise. No clear conduct error is established by these four messages.

**One practice:** on the next change with a state/freshness requirement, the person
writes one falsifiable expected behavior before accepting the assistant's output,
then interprets the actual receipt against it. The model may help prepare the
check. Retain requirement, chosen check, result and acceptance/revision decision.
Success: the decision explicitly responds to the observed result, including a
failure. Counterexample: acceptance relies only on “all checks passed.” Revisit
after that task, noting assistance and task differences; no follow-up is observed yet.

No CV draft was requested. No public project detail, publication or automatic
follow-up is authorized by this example. A future summary would need its own
supported role, content and audience review.
